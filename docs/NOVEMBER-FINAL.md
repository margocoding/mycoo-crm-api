# Финальные правки MyCoo — 11 ноября

## Что изменено

- Партнёр получает личные уведомления и письма о создании, одобрении, отклонении и оплате заявки. В кабинете доступна полная история начислений, в админке — цепочка изменений выплаты с автором и причиной. Регистрация партнёра остаётся открытой.
- Пользователь может состоять в одной действующей компании. Собственник удаляет компанию, участник выходит; после этого можно пройти онбординг заново или принять другое приглашение. При конфликте приглашение не расходуется. Подписка, использованный пробный период и финансовая история сохраняются.
- Удалённая компания становится недоступна участникам, гостям встреч и по общим ссылкам записей. Приглашения отзываются, повторяющиеся задачи отключаются, встречи закрываются, фоновый анализ прекращается. Это логическое удаление: исторические строки и сохранённые файлы физически не стираются.
- Добавлены Яндекс ID и VK ID. Первое связывание с аккаунтом требует подтверждения email; совпадения email из ответа провайдера недостаточно. Последующие входы используют сохранённую идентичность провайдера. Парольный вход остаётся доступным.
- Исправлены мобильный выход, слои шапки AI COO, общий фон и отступы. AI COO читает публичные ссылки из вопроса и показывает источники; детали ограничений — в `ai-coo.md`.
- В звонках появились счётчик непрочитанных сообщений, настройки устройств и режим прослушивания, восстановление после временного обрыва. Запись и выдача общей ссылки доступны только организатору. Ссылка открывает одну запись без протокола и данных компании, действует семь дней и может быть отозвана. Уже выданный адрес скачивания действует не более пяти минут.
- Запись связана с конкретным сегментом и Egress ID. Распознавание и AI-анализ вынесены в очередь `meetings-background`, чтобы не задерживать остановку записи и отзыв доступа.

## Обновление сервера

Dockerfile и workflow не изменялись. Используются существующие PostgreSQL, Redis, SMTP, GigaChat, LiveKit/Egress и хранилище записей.

1. Обновить микросервис звонков: он принимает идентификатор сегмента при старте и конкретный Egress ID при остановке. Старые запросы без этих полей остаются совместимыми.
2. Перед запуском обновлённого API выполнить `npx prisma migrate deploy`. Новые миграции: `20261111120000_workspace_oauth`, `20261111150000_meeting_recording_access`, `20261111170000_partner_notifications`. Существующие партнёрские миграции тоже должны быть применены.
3. Собрать и перезапустить API штатным способом. Фоновые очереди запускаются в нём; Redis должен сохранять данные между перезапусками. Настройки подключения не меняются.
4. Собрать и опубликовать фронтенд. Сохранить SPA fallback для `/auth/oauth/callback` и `/meetings/recordings/:token`, как для остальных маршрутов.

Изменения основаны на партнёрских PR backend #38 и frontend #53, уже объединённых в `main`.

### Вход через Яндекс и VK

Зарегистрировать приложения провайдеров и указать точные разрешённые callback-адреса публичного API:

- Яндекс: `https://API_HOST/api/auth/oauth/yandex/callback`.
- VK: `https://API_HOST/api/auth/oauth/vk/callback`.

На API задать `YANDEX_ID_CLIENT_ID`, `YANDEX_ID_REDIRECT_URI`, при необходимости `YANDEX_ID_CLIENT_SECRET`; для VK — `VK_ID_CLIENT_ID`, `VK_ID_REDIRECT_URI`. `APP_URL` должен указывать на публичный фронтенд. Поля добавлены пустыми в `.env.example`; настоящие ключи в репозитории не хранятся. Без настройки кнопка соответствующего провайдера недоступна.

Включить доступ к email и данным профиля. OAuth state и одноразовые билеты хранятся в Redis десять минут, браузерный обмен привязан к PKCE. После настройки проверить первый вход с подтверждением email, повторный вход, отмену входа и принятие приглашения.

### Письма партнёрам

Используются существующие `SMTP_*`, `MAIL_FROM` и `APP_URL`. Уведомление записывается в одной транзакции с изменением выплаты; письмо обрабатывается отдельно, при сбое повторяется. Перезапуск не теряет ожидающие письма. SMTP не гарантирует строго однократную доставку: при сбое между принятием письма сервером и записью результата возможен повтор с тем же Message-ID.

## Проверка

Локально прошли тесты, линтеры/проверка типов и сборки всех трёх проектов: API — 272 теста, фронтенд — 37, микросервис — 50. В отдельной PostgreSQL-базе применены все 23 миграции; дополнительно прошли 22 партнёрских и 8 workspace/OAuth интеграционных сценариев. Внешние OAuth-провайдеры и SMTP в этих проверках заменены тестовыми ответами. Загрузка текста публичной страницы отдельно проверена реальным запросом; обращение к локальному адресу отклонено.

В браузере проверены ширины 390 и 1366 px: вход по email, выход и защита закрытого маршрута после выхода, подтверждение удаления компании с отменой, шапка и контекст AI COO, уведомления партнёра, история заявки в админке, создание локальной встречи и обработка недоступной ссылки на запись. При ненастроенном сервисе звонков интерфейс показывает недоступность видеосвязи; подключение к устройствам и настоящий созвон в этом прогоне не выполнялись.

После выкладки нужен реальный созвон: повторная запись, скачивание по общей ссылке и её отзыв, выборочное выключение микрофона, непрочитанные сообщения, временный обрыв сети. Отдельно проверить iPhone/Android при блокировке экрана. Сайт учитывает поддержку захвата экрана и сохраняет выбор устройств, но не может изменить ограничения браузера, системные разрешения или запрет фоновой работы ОС.
