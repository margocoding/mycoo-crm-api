# Проверка полноты черновика протокола

В сквозном тесте 17.10.2026 SpeechKit вернул полную расшифровку, но GigaChat пропустил действие без назначенного исполнителя и срока. Парсер допускает такие задачи; потеря происходила при генерации ответа. Инструкция модели уточняет, что неизвестные поля нужно оставить пустыми, сохранив само поручение и открытый вопрос. Черновик по-прежнему требует проверки человеком перед публикацией.

Свободный JSON также мог не содержать обязательные поля задачи. Запрос протокола теперь использует `response_format` с `type=json_schema`, обязательными полями и `strict=true` по [документации GigaChat](https://developers.sber.ru/docs/ru/gigachat/guides/structured-output). Локальная строгая проверка остаётся: некорректный результат не публикуется и диагностируется как `Invalid model response`, без записи текста встречи в логи. Другие запросы AI не получают схему протокола.

## Регрессионный сценарий

Дата встречи: 17.10.2026, Europe/Moscow. В департаменте есть Иван Петров и Анна Смирнова, с разными идентификаторами пользователей.

Текст для произнесения в тестовом звонке:

> Это синтетическая тестовая встреча. Сегодня семнадцатое октября две тысячи двадцать шестого года. Мы приняли три решения. Иван Петров подготовит отчёт по продажам до двадцатого октября две тысячи двадцать шестого года. Анна Смирнова согласует бюджет до двадцать второго октября две тысячи двадцать шестого года. Ещё нужно обновить сайт, но ответственного и срок пока не определили. На этом встреча закончена.

После остановки записи и завершения встречи дождаться `recordings[].status=ready` и `analysisStatus=draft` через основной API. Текст должен поступить из MP4 через штатный worker, SpeechKit и GigaChat.

Проверить смысл результата, без требования дословных заголовков:

| Действие | Исполнитель | Срок |
| --- | --- | --- |
| Подготовить отчёт по продажам | ID Ивана Петрова | `2026-10-20` |
| Согласовать бюджет | ID Анны Смирновой | `2026-10-22` |
| Обновить сайт | `[]` | `null` |

Также проверить:

- В `openQuestions` осталось уточнение ответственного/срока по сайту.
- `successCriteria` пусты: критерии приёмки не обсуждались.
- `summary` описывает содержание, а не повторяет название встречи.
- `publishedAt=null`; автоматически опубликованных задач нет.
- В приватном S3 появился MP4 с аудио и видео, неподписанный GET возвращает 403, ссылка основного API — 200.

Это проверка ответа реальной модели. Модульный тест парсера с подготовленным JSON не подтверждает полноту генерации. Один успешный сценарий также не гарантирует качество всех будущих протоколов; ручная проверка черновика сохраняется.
