# Завершение и повторение задач

На дашборде просроченную задачу может завершить собственник, руководитель или администратор доступного департамента, а также её первоначальный создатель. Используется существующий маршрут изменения статуса; запрос AI-пересчёта сохраняется как прежде. Редактирование и удаление по-прежнему ограничены иерархией назначения.

`createdById` сохраняется при создании и не меняется при переназначении. Для задач до миграции первоначальный создатель неизвестен: `assignedById` мог меняться, поэтому он не копируется. Для таких задач доступны права завершения по роли.

## Расписание

В `POST/PATCH /api/workspace/:workspaceId/departments/:departmentId/tasks` можно передать `repeatDays`: уникальные числа от 1 (понедельник) до 7 (воскресенье). Пустой массив отключает повторы; отсутствие поля при PATCH сохраняет расписание. Другие поля и проверки назначений остаются прежними.

Исходная задача создаётся сразу с указанными датами. Следующая появляется после даты начала и текущего дня в ближайший выбранный день в 00:00 по Москве. Например, задача на 5–6 октября с повтором по понедельникам создаст следующий экземпляр на 12–13 октября. Выбор всех семи дней даёт ежедневное повторение.

Каждый экземпляр — отдельная задача в Backlog, с актуальными на момент создания названием, интервалом выполнения, критерием, приоритетом, департаментами и исполнителями исходной задачи. Сохраняются создатель и уровень назначения. Назначения создают обычные уведомления; ожидающие приглашения связываются с пользователем при принятии ссылки.

Редактирование исходной задачи влияет только на будущие экземпляры. Изменение дней или даты начала пересчитывает ближайший повтор от текущего момента, без создания прошлых задач. Завершение исходной задачи не отменяет расписание. Отключить его можно пустым `repeatDays` или удалением исходной задачи; уже созданные экземпляры сохраняются. В экземпляре расписание не настраивается.

## Очередь и обновление

BullMQ `task-recurrence` использует существующий `REDIS_URL` и один планировщик `scan` раз в минуту. Курсор следующего повтора хранится в PostgreSQL. После перезапуска API или Redis планировщик восстанавливается, пропущенные даты обрабатываются по одному экземпляру на исходную задачу за проход (до 100 исходных задач за проход). Создание экземпляра, уведомлений и сдвиг курсора выполняются одной транзакцией под блокировкой компании; уникальный ключ `(repeatSourceId, repeatDate)` защищает от повторов.

Для неактивных компаний и истёкших подписок генерация приостановлена. После восстановления доступа оставшееся расписание продолжает обрабатываться. Без департаментов расписание отключается.

Перед запуском: `npx prisma migrate deploy`, `npx prisma generate`, `npm run build`. Нужны миграции `20261004090000_referral_discounts_task_creator` и `20261004091000_recurring_tasks`. Отдельный процесс, новые секреты, изменения Docker и зависимостей не требуются.
