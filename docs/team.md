# Департаменты и приглашения

Департаменты, участники и роли сохраняются в PostgreSQL. Роль относится к участию
в конкретном департаменте: один пользователь может иметь разные роли в разных отделах.
Задачи, канбан и показатели департаментов в этот этап не входят.

## Запуск

Перед запуском обновлённого API примените миграцию 20260915090000_team_departments
к нужной базе штатным способом:

    npx prisma migrate deploy

При локальной сборке после изменения схемы:

    npx prisma generate
    npm run build

Новых переменных окружения не требуется. Используются существующие PostgreSQL,
Redis и настройки JWT. Конфигурация Docker и CI/CD не меняется.

## Права

- Владелец компании создаёт департаменты после диагностики и управляет всей командой.
- Создатель становится первым начальником департамента.
- Начальник назначает роли, приглашает и удаляет участников.
- Администратор управляет участниками, но не может назначать, менять или удалять начальника.
- Работник получает только собственные записи участия. Список коллег и приглашений ему не возвращается.
- При назначении нового начальника предыдущий становится администратором. Удаление или понижение единственного начальника блокируется.
- В новом департаменте участник получает роль работника. Привязки вне доступных руководителю департаментов сохраняются.
- Удаление последней привязки закрывает доступ к компании; владелец компании сохраняет свой доступ.
- Анкета и диагностика компании возвращаются только владельцу. Остальным участникам доступны название и состояние рабочего пространства.

## API

Все маршруты команды требуют Bearer JWT. Компания задаётся в пути;
пользователь и его права определяются сервером.

| Метод | Путь после /api | Назначение |
| --- | --- | --- |
| GET | /workspace/:workspaceId/team | Доступные департаменты, участники, ожидающие приглашения |
| POST | /workspace/:workspaceId/team/departments | Создать департамент |
| PATCH | /workspace/:workspaceId/team/departments/:departmentId | Название и описание |
| POST | /workspace/:workspaceId/team/departments/:departmentId/invitations | Создать или перевыпустить ссылку |
| DELETE | /workspace/:workspaceId/team/invitations/:invitationId | Отменить приглашение |
| PATCH | /workspace/:workspaceId/team/departments/:departmentId/members/:userId | Изменить роль |
| DELETE | /workspace/:workspaceId/team/departments/:departmentId/members/:userId | Удалить из департамента |
| PATCH | /workspace/:workspaceId/team/members/:userId/departments | Выбрать департаменты участника |
| GET | /invitations/:token | Проверить приглашение без авторизации |
| POST | /invitations/:token/accept | Принять приглашение с паролем; получить сессию и идентификаторы компании и департамента |

Приглашение действует семь дней и принимается один раз. В базе хранится SHA-256
хеш случайного токена. Сам токен возвращается только при создании ссылки.
Перевыпуск ссылки отменяет предыдущую для того же адреса и департамента.
Если приглашающий потерял необходимые права, ссылка не принимается.

Новый участник задаёт пароль; существующий подтверждает действующий пароль своего
аккаунта. Приглашение не сбрасывает чужой пароль. Попытки входа существующего
пользователя ограничиваются по аккаунту через Redis, в том числе при перевыпуске ссылки.

Письма автоматически не отправляются. Фронтенд формирует ссылку на своём домене
и даёт скопировать ссылку или текст приглашения для самостоятельной отправки.
