# Дашборд

`GET /api/workspace/:workspaceId/dashboard?departmentId=...`, авторизация Bearer JWT.

Без departmentId собственник получает всю компанию; остальные — свой первый департамент. Явно указанный отдел проверяется по текущему членству. Собственник переключается между всеми отделами, руководитель и администратор получают AI-сводку только своего отдела, сотрудник — только назначенные ему задачи и своё участие, без AI-анализа. Права проверяются при каждом запросе, сохранённая сводка не даёт дополнительных прав.

Задачи: активные — все статусы кроме done; просроченные — незавершённые со сроком раньше текущего дня; выполненные — done за всё время. Список показывает три ближайших по сроку активных задачи, включая просроченные. Общая задача считается один раз по ID в сводке компании. Команда — уникальные участники департаментов, принявшие приглашение, без собственника; руководители (CHIEF) входят в это общее число. Человек в нескольких отделах учитывается один раз. В личном обзоре сотрудника считаются только его задачи и участие.

## AI-сводка

Один запрос GigaChat рассчитывает риски, рекомендацию и оценку прогресса цели. Используется общий GigachatService: существующие OAuth, сертификаты, таймауты и повторы. Ответ проходит проверку структуры, диапазона процента 0–100, длины текстов и списка рисков. Процент — оценка AI, а не измерение бизнес-результата. Если нет цели или задач недели, вместо процента возвращается null; модель также может вернуть null при недостатке данных.

Неделя — семь календарных дней, включая текущий день, по Москве. В выборку входят задачи, созданные, изменённые или запланированные на этот интервал. Недельные показатели используют текущее состояние этих задач; отдельной истории изменения статусов пока нет. Контекст включает цель и приоритеты из брифа, текущие активные/просроченные задачи, точные счётчики всех задач недели и до 80 описаний с ближайшими сроками. Длинные описания ограничиваются, для задачи передаются до пяти исполнителей без email, а также до 50 примеров сводок отделов. Ограниченные выборки явно обозначены как примеры. Связи общей задачи с чужими отделами не передаются в анализ отдельного департамента.

Результат хранится в dashboard_snapshots отдельно для компании и каждого департамента. Первый запрос собственника или управляющего регистрирует сводку и запускает расчёт в фоне. Затем она обновляется раз в 24 часа после успешного расчёта, даже без открытой страницы. Проверка очереди выполняется внутри API раз в минуту; после перезапуска сервер подхватывает просроченные расчёты. Неактивные компании пропускаются. Сканируется до 10 записей за цикл без параллельного выполнения циклов.

Атомарный захват записи в PostgreSQL предотвращает двойные расчёты при одновременных запросах и нескольких экземплярах API. Зависший захват можно повторить после полного таймаута GigaChat плюс одна минута; результат сохраняется только владельцем актуального захвата. При ошибке остаётся предыдущая сводка, следующая попытка — через 15 минут. Ошибка первой генерации не подменяется нулевыми рисками или выдуманным процентом. В API состояния ready/updating/stale/unavailable/restricted и даты расчёта/периода.

Клиент обновляет текущие показатели раз в минуту и при возвращении на страницу, во время расчёта — раз в пять секунд. Повторный GET не пересчитывает свежую AI-сводку. Встречи и операционный журнал на этом этапе остаются пустыми, счётчики встреч — нули. Кнопки имитации принятия рекомендации убраны; автоматическое создание задач не реализуется.

## Обновление

Применить миграцию `20260921100000_dashboard_snapshots`, выполнить `npx prisma generate` и собрать API. Затем обновить клиент. Миграция добавляет только таблицу сводок и индекс, существующие задачи и роли не меняет. Используются прежние GIGACHAT_* переменные; новых переменных, пакетов, cron-контейнеров и правок Docker/CI нет.

Описание формата запроса: [GigaChat — генерация ответа](https://developers.sber.ru/docs/ru/gigachat/api/reference/rest/post-chat).
