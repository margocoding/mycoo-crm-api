# Подписки и реферальная программа

Подписка принадлежит аккаунту собственника и определяет доступ к его рабочим пространствам для всех участников. После успешной диагностики один раз запускается пробный период на 10 дней. Создание новых пространств и повторная диагностика его не перезапускают.

## Реферальная программа

`GET /api/billing/me` возвращает собственную подписку, постоянную ссылку `APP_URL/?ref=…`, число регистраций, начисленные и ожидающие запуска дни. Список email приглашённых не возвращается.

Фронтенд сохраняет код ссылки в sessionStorage (на срок до 30 дней в этой вкладке) и передаёт `referralCode` в `POST /api/auth/register`. Новый переход по ссылке заменяет ранее сохранённый код. После входа или регистрации код очищается. Уже вошедшим пользователям код не назначается.

После регистрации с подтверждённым email пригласивший получает 30 дней:

- Если срок ещё действует — к текущей дате окончания.
- Если закончился — 30 дней от текущего момента, доступ восстанавливается.
- Если триал ещё не запускался — дни сохраняются и добавляются к первому триалу или первой оплаченной подписке.

Начисление и регистрация выполняются одной транзакцией. Уникальная запись на нового пользователя и блокировка начислений на аккаунт защищают от повторов и потери дней при одновременных регистрациях. Неизвестный код игнорируется; повторный вход, существующий аккаунт и собственная ссылка не дают бонуса. Обычные приглашения сотрудников в департамент — отдельный механизм, без реферального бонуса.

## Тарифы и доступ

`GET /api/billing/plans` — публичный каталог. Источник цен — `src/billing/billing.plans.ts`; суммы хранятся в копейках.

| Тариф | Месяц | Год: 12 месяцев по цене 10 |
| --- | ---: | ---: |
| Старт / START | 29 900 ₽ | 299 000 ₽ |
| Контроль / MISSION | 49 900 ₽ | 499 000 ₽ |
| Опердир / ENTERPRISE | 99 900 ₽ | 999 000 ₽ |

Публичные названия и описания обновлены по условиям от 28.09.2026. Внутренние идентификаторы сохранены для совместимости подписок и заказов. «Контроль» — популярный тариф. Позиционирование: «Видеть → Управлять → Освободиться». Названия, описания, выделение и цены лендинг и окно подписки получают из одного серверного каталога. Годовая оплата даёт 12 календарных месяцев; два месяца в подарок соответствуют экономии 1/6 годовой стоимости, а не 20%.

Перечень возможностей в каталоге описывает продуктовую концепцию тарифов. Это обновление названий и условий, а не реализация встреч, AI-чата, базы знаний, KPI или автоматических отчётов. Упомянутые в исходном описании размеры команд — примеры аудитории, а не согласованные технические квоты.

По окончании срока рабочие API команды, задач, дашборда и уведомлений возвращают HTTP 402 с `code: SUBSCRIPTION_EXPIRED`. Учётная запись, метаданные доступных пространств, тарифы и реферальная ссылка остаются доступны. Интерфейс показывает страницу подписки; локальная дата окончания используется для обновления экрана, сервер всегда проверяет срок самостоятельно. Покупка собственной подписки сотрудником не открывает пространство с просроченной подпиской его собственника.

Очередь AI не запускает новые расчёты для просроченных аккаунтов. Сохранённые данные не удаляются. Каркас учитывает выбранный **оплаченный** тариф и срок; отдельные квоты пользователей и разграничение функций между тарифами пока не вводятся.

## Подключение Робокассы

Платёжный провайдер намеренно не подключён. `PaymentGateway.available = false`, создание оплаты возвращает HTTP 503, интерфейс показывает недоступность оплаты. Выбор тарифа не выдаёт доступ. Фальшивых успешных оплат и отправок счетов нет.

Для подключения:

1. Реализовать `PaymentGateway.checkout(order)` с созданием/возвратом HTTPS-ссылки Робокассы для сохранённого заказа. Один заказ должен соответствовать одному счёту провайдера; повторные вызовы должны возвращать ту же оплату. Затем включить `available` при наличии конфигурации.
2. Клиент вызывает `POST /api/billing/orders` с `plan`, `period: MONTH | YEAR`, UUID `idempotencyKey` и необязательным `workspaceId`. Для пространства проверяется собственник; цена рассчитывается только сервером. Повтор запроса с тем же ключом возвращает тот же ожидающий заказ. Замена тарифа/периода с прежним ключом отклоняется.
3. Добавить серверный обработчик уведомления Робокассы. **Проверить подпись, статус оплаты, идентификатор счёта, сумму и валюту по правилам провайдера**, затем вызвать `BillingService.confirmVerifiedPayment(orderId, providerPaymentId, amountKopecks, 'RUB')`. Метод доступен через `BillingCoreModule`. Публичного маршрута активации по данным браузера нет.
4. Направлять пользователя после оплаты на `/subscription`. Экран перечитывает состояние раз в 30 секунд; после подтверждения появляется переход в рабочее пространство. Возврат пользователя с платёжной страницы сам по себе не подтверждает оплату.

Подтверждение атомарно переводит заказ в PAID и добавляет календарный месяц/год к `max(сейчас, activeUntil)`, сохраняя остаток триала и реферальные дни. Повторное уведомление не продлевает срок повторно; другой платёж для уже оплаченного заказа, неверные сумма/валюта и повторное использование идентификатора платежа не принимаются. Автоматические списания, чеки, возвраты и выставление счетов в этот каркас не входят.

## Обновление

Перед запуском обновлённого API: `npx prisma migrate deploy`, `npx prisma generate`, обычная сборка и запуск проекта. Миграция `20260927130000_subscriptions_referrals` сохраняет существующие подписки и переносит самый ранний старт триала из пространств. Старым пользователям не выдаётся новый триал: уже истёкший срок после обновления закроет доступ.

Нужен существующий `APP_URL` с публичным адресом фронтенда. Новых секретов на этом этапе нет. Docker, CI и зависимости не меняются.

Проверки: `npm test`, `npm run build`, `npm run lint`; дополнительно локально проверены регистрация, одновременные начисления, блокировка API, продление и идемпотентность оплат на PostgreSQL. Подключение реальной Робокассы требует отдельной проверки её checkout и подписанного уведомления.
