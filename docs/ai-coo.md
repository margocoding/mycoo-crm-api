# AI COO

Раздел консультирует пользователя по компании, задачам и документам через существующий GigaChat. Чат ничего не изменяет в задачах и не выполняет рекомендации автоматически.

## Запуск

Перед обновлением API применить миграции штатной командой `prisma migrate deploy`, затем собрать и запустить приложение. Миграция `20261027120000_ai_coo_chat` добавляет только таблицы чатов, сообщений и документов. Dockerfile, workflow, Redis и сервис звонков не меняются.

Используются существующие серверные `GIGACHAT_CREDENTIALS`, `GIGACHAT_SCOPE`, `GIGACHAT_MODEL` и настройки доверенных сертификатов. Необязательный `GIGACHAT_COO_MODEL` выбирает отдельную модель для чата; по умолчанию применяется `GIGACHAT_MODEL`. Ключи остаются на сервере. Прокси должен допускать multipart-запросы немного больше 10 МБ и ожидание ответа модели до настроенного `GIGACHAT_TOTAL_TIMEOUT_MS` (по умолчанию 120 секунд).

## Контекст и доступ

- Собственник выбирает всю компанию или отдельный департамент. Руководитель и администратор получают данные доступного департамента; сотрудник — свои назначения и созданные им задачи в нём. Подписка и членство проверяются сервером.
- Перед каждым ответом собираются задачи за семь календарных дней по московскому времени: созданные/изменённые в периоде либо с пересекающим его интервалом выполнения. Передаются точные счётчики и до 80 примеров в пределах 36 000 символов. Отдельно учитываются все текущие просрочки. Ограниченность выборки сообщается модели.
- Используется последняя сохранённая сводка дашборда для выбранной области, с датой и признаком устаревания. Отсутствующая сводка не подменяется вымышленной. Сотрудникам общая AI-сводка не передаётся. Чат не запускает дополнительный пересчёт дашборда.
- Переписка и документы изолированы по пользователю, компании и области доступа. При понижении роли прежний управленческий диалог недоступен. В интерфейс возвращаются последние 25 пар сообщений; в модель — до 12 последних успешных пар, до 24 000 символов. Слишком длинная последняя пара сокращается с явной пометкой.

## Документы

До пяти документов на диалог, до 10 МБ каждый: PDF, DOCX, XLSX, PPTX. Файл отправляется сервером в GigaChat с `purpose=general`. В БД хранятся метаданные и закрытый идентификатор провайдера; бинарные файлы на серверном диске не сохраняются. Клиент не получает идентификаторы GigaChat. Не нужны новое файловое хранилище или S3.

Все документы текущего диалога участвуют в следующем запросе. Удаление убирает документ у провайдера и из активного контекста; уже сохранённые сообщения остаются частью переписки. Документы большого объёма могут не поместиться в контекст модели, даже если файл меньше лимита. Чтение одностраничного PDF-скана без текстового слоя проверено на чётком печатном тексте; качество распознавания сложных сканов и рукописей не гарантируется.

## API

Все маршруты под `/api/workspace/:workspaceId/ai-coo`, с Bearer JWT и действующей подпиской:

- `GET /?departmentId=…` — история, документы и сводка контекста. Без отдела собственник получает компанию, остальные — первый доступный отдел.
- `POST /messages` — `{text, requestId, departmentId?}`. Текст до 8000 символов; `requestId` — UUID v4. Пустой текст допустим при наличии документов. Возвращается обновлённый диалог.
- `POST /documents?departmentId=…` — multipart с одним полем `file`.
- `DELETE /documents/:documentId?departmentId=…` — удаление документа своего диалога.

`requestId` защищает от дублирования сохранённых сообщений после потери ответа. Повтор использует тот же текст и идентификатор. В одном диалоге выполняется одна операция; блокировка сохранена в PostgreSQL и истекает после тайм-аута, поэтому перезапуск не блокирует чат навсегда. Поздний ответ не перезаписывает результат более нового запроса. Окно до 30 попыток за пять минут на диалог включает повторы после ошибок. Сбой провайдера сохраняет вопрос со статусом `failed`, позволяя повторить отправку.

## Проверка

Unit-тесты проверяют границы доступа, период задач, ограничения контекста, историю, повторы, блокировки, смену роли, валидацию документов и протокол GigaChat. Отдельные локальные проверки используют выделенную PostgreSQL-базу и HTTP-провайдер с тестовыми ответами. Реальный GigaChat-2 проверен на синтетических DOCX, PDF, XLSX, PPTX и PDF-скане: извлечение фактов из содержимого и удаление загруженных файлов. Для DOCX также проверены продолжение диалога и полный путь через API с контекстом задач. Для XLSX и PPTX используются стандартные OOXML MIME-типы — альтернативные типы из руководства провайдера при живой проверке не сработали. Реальные документы заказчика не отправлялись.
