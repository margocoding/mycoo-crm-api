# Meetings

The main API stores meetings in a workspace and one department. Only the owner or a department manager/admin can create a meeting. Invitees must belong to that department (the workspace owner is also allowed). A workspace owner can inspect/manage any meeting; other users require both a current department membership and an active invitation. LiveKit roles are host/cohost/participant, separate from workspace roles. A cohost can moderate, but publishing the protocol additionally requires task-management rights. Expired subscriptions cannot enter a room.

Apply migrations, configure `CALLS_SERVICE_URL` and a matching random `CALLS_SERVICE_SECRET` (32+ characters), then start normally. Deployment files of the main API are unchanged. The calls repository documents LiveKit/Egress/S3/SaluteSpeech infrastructure and signed webhooks. Existing Redis and GigaChat configuration is reused; SMTP delivers meeting invitations and protocol notices through the existing notification outbox.

Main routes are under `/api/workspace/:workspaceId/meetings`: list/create, get/edit `/:id`, `/:id/join`, `/:id/actions`, notes, prepare, transcript, protocol/publish, and recording URL/retry. `POST /api/meetings/events` accepts only the private service secret and rechecks LiveKit join events. Never expose service credentials to the browser.

Recording and transcription state, external upload/task IDs and retry deadlines are persisted in PostgreSQL. BullMQ schedules recovery scans every 15 seconds; DB leases prevent concurrent processing by multiple API instances. AI analysis is queued after the meeting ends and recordings finish processing. A manually submitted transcript has precedence over recordings. Recognition and GigaChat calls run off-request; no browser needs to stay open. Failed processing is visible and can be retried. Transcripts are limited to 250,000 characters and are split for GigaChat; unknown assignees remain unassigned. GigaChat sees only names/IDs in the meeting's department plus its owner.

The AI protocol is a draft. A manager reviews decisions, task assignees, dates and success criteria before publishing. Task creation, meeting source links, publication and notifications commit together under the existing workspace transaction lock. Duplicate publication does not create duplicate tasks. A following meeting keeps the previous meeting link, and AI preparation uses published results and up to 100 relevant department tasks. It does not fabricate KPI or document data that has no connected source.

This stage covers the MVP meeting → recording → asynchronous transcript → reviewed protocol → tasks → next meeting. Streaming transcription/coaching during a call, corporate memory search, monthly management analytics, external guests and KPI/document connectors are separate features. LiveKit chat is for the active call and is not archived by the main API.

Local tests use synthetic model/provider responses; production recognition requires the project's SaluteSpeech credentials and a deployed Egress/storage setup. Recheck a real audio recording through SaluteSpeech and the final production TLS/TURN topology before launch.
